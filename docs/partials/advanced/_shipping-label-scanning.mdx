Shipping Label Scanning reads a shipping label and returns its tracking ID, the receiver's name and address, and the carrier. Like receipt scanning, it uses the Adaptive Recognition Engine, which processes the label in the cloud.

To read your own set of fields on the device instead, define a <DocLink framework={props.framework} page="label-definitions">custom label</DocLink>.

:::warning Beta
Shipping Label Scanning requires the Adaptive Recognition Engine, which is still in beta and may change in future versions of Scandit Data Capture SDK. To enable it on your subscription, contact [support@scandit.com](mailto:support@scandit.com).
:::

## Before you start

- Use Scandit Data Capture SDK 8.6.0 or later. Shipping Label Scanning is available on iOS, Android, and Web. It isn't available on other frameworks yet.
- Ask [support@scandit.com](mailto:support@scandit.com) to enable the Adaptive Recognition Engine on your subscription.
- Make sure the device has a network connection. The Adaptive Recognition Engine processes the label in the cloud.
- Set up a `LabelCapture` instance and a `DataCaptureView`. If you haven't done this yet, follow <DocLink framework={props.framework} page="get-started">Get started</DocLink>.

Create the `LabelCapture` instance with <ApiLink framework={props.framework} page={labelSettingsPage} anchor="class-scandit.datacapture.label.LabelCaptureSettings">LabelCaptureSettings</ApiLink> that have no label definitions. The overlay adds its own definition for the tracking barcode. Label definitions that you add stay active alongside it, so a barcode that isn't the tracking barcode can end up as the `trackingId`.

```kotlin
import com.scandit.datacapture.label.capture.LabelCapture
import com.scandit.datacapture.label.capture.LabelCaptureSettings

val labelCaptureSettings = LabelCaptureSettings.builder().build()
val labelCapture = LabelCapture.forDataCaptureContext(dataCaptureContext, labelCaptureSettings)
```

</Only>

## Steps

### 1. Create the settings

Create <ApiLink framework={props.framework} page={settingsPage} anchor={`class-${settingsAnchor}`}>LabelCaptureAdaptiveRecognitionSettings</ApiLink> with the result type <ApiLink framework={props.framework} page={resultTypePage} anchor="value-scandit.datacapture.label.AdaptiveRecognitionResultType.ShippingLabel">{symbolTokens[props.framework].shippingLabel}</ApiLink>. The result type sets the kind of document that the overlay looks for.

<Only when={props.framework === 'web'}>

`create()` is asynchronous. If you call it without a result type, it creates settings for receipts.

</Only>

To change the hint that the overlay shows while it processes a label, use <ApiLink framework={props.framework} page={settingsPage} anchor={symbolTokens[props.framework].processingHintAnchor}>{symbolTokens[props.framework].processingHint}</ApiLink>.

<Only when={props.framework === 'android'}>

### 3. Listen for results

Set a <ApiLink framework={props.framework} page={listenerPage} anchor={`interface-${listenerAnchor}`}>{symbolTokens[props.framework].listener}</ApiLink> as the overlay's <ApiLink framework={props.framework} page={overlayPage} anchor={`property-${overlayAnchor}.Listener`}>{symbolTokens[props.framework].listenerProperty}</ApiLink>. It receives two callbacks:

- <ApiLink framework={props.framework} page={listenerPage} anchor={`method-${listenerAnchor}.OnRecognized`}>{symbolTokens[props.framework].onRecognized}</ApiLink> runs when the label is recognized. Check that the result is a <ApiLink framework={props.framework} page={resultPage} anchor="class-scandit.datacapture.label.ShippingLabelScanningResult">ShippingLabelScanningResult</ApiLink>, then read its fields.
- <ApiLink framework={props.framework} page={listenerPage} anchor={`method-${listenerAnchor}.OnFailure`}>{symbolTokens[props.framework].onFailure}</ApiLink> runs when recognition fails, for example because of a connection error.

<Only when={props.framework === 'ios'}>

The overlay holds its delegate weakly, so keep a strong reference to the delegate object.

</Only>

<Only when={props.framework === 'android'}>

```kotlin
# import com.scandit.datacapture.label.ui.overlay.adaptiverecognition.AdaptiveRecognitionResult
# import com.scandit.datacapture.label.ui.overlay.adaptiverecognition.LabelCaptureAdaptiveRecognitionListener
# import com.scandit.datacapture.label.ui.overlay.adaptiverecognition.LabelCaptureAdaptiveRecognitionOverlay
# import com.scandit.datacapture.label.ui.overlay.adaptiverecognition.ShippingLabelScanningResult
# lateinit var overlay: LabelCaptureAdaptiveRecognitionOverlay
overlay.listener = object : LabelCaptureAdaptiveRecognitionListener {
    override fun onRecognized(result: AdaptiveRecognitionResult) {
        val shippingLabel = result as? ShippingLabelScanningResult ?: return

        val trackingId = shippingLabel.trackingId
        val receiverName = shippingLabel.receiverFullName
        val receiverCompany = shippingLabel.receiverCompany // null if the label doesn't show one
        val carrier = shippingLabel.carrier
    }

    override fun onFailure() {
        // Recognition failed, for example because of a connection error.
    }
}
```

</Only>

### 4. Switch the camera back on

When the overlay starts to process a label, it switches the camera to standby. It doesn't switch the camera back on after a result. To scan the next label, call the camera's <ApiLink framework={props.framework} page={cameraPage} anchor={symbolTokens[props.framework].cameraOnAnchor}>{symbolTokens[props.framework].cameraOn}</ApiLink> in <ApiLink framework={props.framework} page={listenerPage} anchor={`method-${listenerAnchor}.OnRecognized`}>{symbolTokens[props.framework].onRecognized}</ApiLink> after you handle the result.

<Only when={props.framework === 'web'}>

If recognition fails, the overlay shows an error notification and switches the camera back on.

</Only>

<Only when={props.framework === 'android'}>

## Verify it works

You're done when:

- The overlay shows its processing hint after you point the camera at a shipping label.
- Your <ApiLink framework={props.framework} page={listenerPage} anchor={`method-${listenerAnchor}.OnRecognized`}>{symbolTokens[props.framework].onRecognized}</ApiLink> callback receives a `ShippingLabelScanningResult`, and you can read its `trackingId` and `carrier`.
- Your <code>{symbolTokens[props.framework].onRecognized}</code> code switches the camera back on after each result, so you can scan the next label.

Processing starts only after the SDK decodes a tracking barcode on the label. The tracking barcode must be Code 128, Code 39, ITF, Data Matrix, or PDF417. Processing also requires a license key that includes Adaptive Recognition. If the overlay never shows its processing hint, check that the label has one of these barcodes and that your license key includes Adaptive Recognition.

If <ApiLink framework={props.framework} page={listenerPage} anchor={`method-${listenerAnchor}.OnFailure`}>{symbolTokens[props.framework].onFailure}</ApiLink> runs instead, recognition failed, for example because of a network problem or a label the engine can't read. Check the network connection, then scan the label again.
